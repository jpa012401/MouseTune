**Make an ordinary mouse feel like a trackpad on macOS.** MouseTune is a small menu bar app that adds smooth scrolling, remappable extra buttons, and click-and-drag gestures for Spaces and Mission Control. It supports macOS 12 Monterey through macOS 27, on Apple Silicon and Intel.

> Inspired by [Mac Mouse Fix](https://github.com/noah-nuebling/mac-mouse-fix) by Noah Nuebling. MouseTune was written independently from scratch and contains no Mac Mouse Fix source code. See [CREDITS.md](CREDITS.md).

**Status:** personal project, version 0.1.x. Phases 0–7b are merged on `main`. Hardware acceptance on real mice and older macOS versions is still in progress (see the [Release checklist](#release-checklist)). There are no published downloads yet, so to use it, [build it yourself](#creating-a-release).

## Features

- **Smooth scrolling** for wheel mice, with acceleration, momentum, Safari rubber-banding, an adjustable curve, and *precise when scrolling slowly*.
- **Scroll modifiers**: Shift scrolls sideways, Option scrolls precisely, and a key of your choice scrolls faster. You can invert vertical scrolling.
- **Button remapping** for buttons 3–5 and beyond, on click, double click or hold. A button can trigger a keyboard shortcut, a system action (Mission Control, Launchpad, Spotlight, Spaces…), a mouse click, or a media or brightness key.
- **Back and Forward** on the side buttons, per app (`⌘[` / `⌘]` where an app expects it).
- **Drag gestures**: hold a button and drag to switch Spaces, open Mission Control or App Exposé, or send a two-finger swipe.
- **Button + scroll**: zoom, or the App Switcher.
- **Leaves your trackpad alone.** Only discrete wheel ticks and button events from external mice are touched. Trackpads, the Magic Mouse and tablets pass through unchanged.
- **Menu bar controls** to turn scrolling or buttons off quickly, plus launch at login and an option to hide the menu bar item.

No accounts, no telemetry, no network access.

## How it works

MouseTune is a [Tauri v2](https://v2.tauri.app) app: a Rust core and a React settings window. The core runs its own input thread, which holds macOS event taps and an IOHID device monitor. It filters events from tracked mice and posts the smoothed or remapped results. Slow work (posting shortcuts, launching actions) runs on a separate executor thread, so the event taps never block mouse input.

It needs one permission, **Accessibility**, to read and post input events.

| Path | What's there |
|---|---|
| `src-tauri/src/input/` | Event taps, scroll and button engines, drag gestures |
| `src-tauri/src/platform/macos/` | Thin wrappers around macOS APIs |
| `src-tauri/src/config/` | Settings file, defaults and validation |
| `src/` | React settings UI (`routes/`, `components/`, `store/`) |
| `src/bindings.ts` | Typed IPC client, generated by `cargo test` |
| `scripts/` | `pnpm release` tooling |

[AGENTS.md](AGENTS.md) holds the architecture, conventions and current state in full.

## Installing

1. [Get a signing certificate](#getting-an-apple-signing-certificate). The free one is enough.
2. [Build a release](#creating-a-release).
3. Open the `.dmg`, drag **MouseTune** to Applications, and launch it.
4. Follow the onboarding screen to turn on MouseTune in **System Settings → Privacy & Security → Accessibility** (on macOS 12: **System Preferences → Security & Privacy → Privacy → Accessibility**).
5. Connect a mouse. Settings → General lists it as tracked.

Settings live in `~/Library/Application Support/com.johnpaulalabe.mousetune/config.json`, and logs in `~/Library/Logs/com.johnpaulalabe.mousetune/`.

**To uninstall:** quit MouseTune (menu bar → Quit, or Settings → Quit), delete it from Applications, and remove it from the Accessibility list. You can also delete the two folders above.

## Development

### Requirements

- macOS 12 or later with the Xcode Command Line Tools: `xcode-select --install`
- Rust stable, 1.95 or newer, with both macOS targets:
  ```sh
  rustup target add aarch64-apple-darwin x86_64-apple-darwin
  ```
- Node 22 or newer and pnpm 9: `corepack enable`

### Getting started

```sh
git clone https://github.com/jpa012401/MouseFix.git mousetune
cd mousetune
pnpm install
pnpm exec vite build     # once, on a fresh clone: Rust won't compile without dist/
pnpm tauri dev
```

### Checks

These are the checks CI runs:

```sh
pnpm typecheck && pnpm test                                  # frontend
cd src-tauri
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test                                                   # also regenerates ../src/bindings.ts
git diff --exit-code -- ../src/bindings.ts                   # must be clean, or commit it
```

`cargo test` rewrites `src/bindings.ts` from the Rust types. Commit it with the Rust change; never edit it by hand.

### Accessibility permission while developing

- **`pnpm tauri dev`** runs an unbundled binary, so macOS attributes the permission to the app that launched it. Grant Accessibility to your terminal or VS Code, not to MouseTune.
- **Bundled builds** need a stable signing identity. Without one, each rebuild looks like a new app and the grant stops working. `pnpm release` refuses to build without one. To clear a stale entry:

  ```sh
  tccutil reset Accessibility com.johnpaulalabe.mousetune
  ```

A clean launch doesn't prove input works. Without Accessibility the taps fail to start and the app still opens normally. Settings → General shows the input engine's real state.

### Contributing

This is a personal project, but issues and pull requests are welcome. Before you change an area, read [AGENTS.md](AGENTS.md). Work test-first, keep event-tap callbacks O(1), and never copy code from Mac Mouse Fix.

## Getting an Apple signing certificate

macOS ties an Accessibility grant to the app's code signature. An app with no signature, or an ad-hoc one, loses the grant on every rebuild. So `pnpm release` needs a real signing identity. There are two kinds:

| | **Apple Development** (free) | **Developer ID Application** (paid) |
|---|---|---|
| Cost | Free, with any Apple ID | Apple Developer Program, US$99/year |
| Good for | Your own Macs | Sharing with anyone |
| Notarized | No: other Macs need a one-time Gatekeeper bypass | Yes: opens normally everywhere |
| `pnpm release` mode | personal | public |

For personal use, the free **Apple Development** certificate is all you need.

### Create a free Apple Development certificate

1. Install **Xcode** from the App Store (the Command Line Tools alone can't create certificates) and open it once.
2. Open **Xcode → Settings… → Accounts**, click **+**, choose **Apple ID**, and sign in. A team named *Your Name (Personal Team)* appears.
3. Select the team, click **Manage Certificates…**, click **+**, and choose **Apple Development**. Xcode creates the certificate and its private key in your login keychain.
4. Check that the identity can sign code:

   ```sh
   security find-identity -v -p codesigning
   ```

   ```
   1) 3F2A…C9E1 "Apple Development: you@example.com (ABCDE12345)"
        1 valid identities found
   ```

5. Copy the whole quoted name. It's your `APPLE_SIGNING_IDENTITY`:

   ```sh
   export APPLE_SIGNING_IDENTITY="Apple Development: you@example.com (ABCDE12345)"
   ```

   Add that line to `~/.zshrc` if you don't want to type it each time. It's a name, not a secret, but keep it out of the repo.

### If it doesn't show up

- **`0 valid identities found`, but the certificate is in Keychain Access:** macOS is missing Apple's intermediate certificate. Download **Worldwide Developer Relations - G3** from [apple.com/certificateauthority](https://www.apple.com/certificateauthority/), double-click it to install, and run the check again.
- **The certificate has no private key** (Keychain Access → *My Certificates* shows no disclosure triangle): it was created on another Mac. Export it as a `.p12` there (right-click → Export, with the key included) and import it here, or create a new one in Xcode.
- **It expired:** Keychain Access shows the expiry date. Create a new one the same way. If Accessibility stops working after you switch certificates, remove MouseTune from the Accessibility list and add it again.

### Using one certificate on several Macs

Export the certificate and private key from Keychain Access (*My Certificates* → right-click → **Export** → `.p12`, with a password), then import the file on the other Mac. Builds signed with the same identity keep their Accessibility grant on that Mac across rebuilds. To run a build on a Mac that doesn't have the certificate, see [Running it on another Mac](#running-it-on-another-mac).

## Creating a release

`pnpm release` builds a signed, universal (Apple Silicon and Intel) `MouseTune.app` and `.dmg`. It refuses to run on a dirty tree, so a build always traces back to a commit.

### 1. Bump the version

The version lives in three files and must match in all of them:

- `package.json` → `"version"`
- `src-tauri/Cargo.toml` → `[package] version`
- `src-tauri/tauri.conf.json` → `"version"` (this one ends up in the app's About box and the DMG's name)

Then let Cargo update `Cargo.lock`, and commit:

```sh
cd src-tauri && cargo check && cd ..
git switch -c release-0.2.0          # or release from main after merging
git commit -am "chore(release): version 0.2.0"
```

Use [semantic versioning](https://semver.org): patch for fixes, minor for features.

### 2. Build

```sh
APPLE_SIGNING_IDENTITY="Apple Development: you@example.com (ABCDE12345)" pnpm release
```

The steps, in order:

1. **Checks the signing setup** and refuses any setup that would give a broken or misleading build: no identity (the build would be ad-hoc signed and lose its Accessibility grant on every rebuild); an identity that isn't Apple Development or Developer ID Application; a Developer ID identity without notarization variables; an Apple Development identity with them; or a partial or doubled set of notarization variables.
2. **Checks that the git tree is clean.**
3. **Runs the CI checks:** `pnpm typecheck`, `pnpm test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and that `src/bindings.ts` is unchanged.
4. **Builds** with `pnpm tauri build --target universal-apple-darwin`.
5. **Verifies the output:** signature, signer, Hardened Runtime, bundle ID, both architectures, and a minimum of macOS 12.0. A public build also checks the notarization ticket and Gatekeeper. It stops at the first failure and says what to do.
6. **Prints a report:** the mode, commit, identity, both paths and the DMG's SHA-256.

The output is in `src-tauri/target/universal-apple-darwin/release/bundle/`:

- `macos/MouseTune.app`
- `dmg/MouseTune_<version>_universal.dmg`

**Prompts to expect:**

- `codesign` asks for keychain access the first time. Choose **Always Allow**.
- Building the DMG may ask to let Terminal (or your editor) control Finder. Allow it.

### 3. Install and smoke-test

Open the DMG, drag MouseTune to Applications (replacing the old copy), and launch it. The first time, grant Accessibility to `/Applications/MouseTune.app`. Later rebuilds signed with the same identity keep the grant. Scroll with a mouse and press a side button before you call it done.

### 4. Tag it

```sh
git tag -a v0.2.0 -m "MouseTune 0.2.0"
git push origin main v0.2.0          # or push the release branch and merge it first
```

### 5. Publish on GitHub (optional)

Attach the DMG and its checksum to a GitHub Release:

```sh
DMG=src-tauri/target/universal-apple-darwin/release/bundle/dmg/MouseTune_0.2.0_universal.dmg
shasum -a 256 "$DMG" > "$DMG.sha256"
gh release create v0.2.0 "$DMG" "$DMG.sha256" --title "MouseTune 0.2.0" --generate-notes
```

A personal (Apple Development) build isn't notarized, so anyone who downloads it has to go through the Gatekeeper bypass below. Before you publish builds for other people, read [Going public later](#going-public-later).

### Running it on another Mac

A personal build isn't notarized, so its first launch on a Mac other than the one that built it needs a Gatekeeper bypass:

- **macOS 12–14:** right-click the app → **Open** → **Open**.
- **macOS 15 and later:** open it once, then go to **System Settings → Privacy & Security** and click **Open Anyway**.

## Going public later

1. Join the [Apple Developer Program](https://developer.apple.com/programs/).
2. Create a **Developer ID Application** certificate (Xcode → Settings → Accounts → Manage Certificates → **+** → Developer ID Application). Then create an App Store Connect API key: App Store Connect → Users and Access → Integrations → Team Keys, role *Developer*. Download the `.p8` file; Apple lets you download it only once.
3. Set these variables:

   ```sh
   export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (ABCDE12345)"
   export APPLE_API_KEY="<key ID>"
   export APPLE_API_ISSUER="<issuer ID>"
   export APPLE_API_KEY_PATH="$HOME/.private_keys/AuthKey_<key ID>.p8"
   ```

   Alternatively, use `APPLE_ID`, `APPLE_PASSWORD` (an [app-specific password](https://support.apple.com/102654)) and `APPLE_TEAM_ID`. Set one method, not both.
4. Run `pnpm release`. It now notarizes, staples the ticket, and checks Gatekeeper.
5. Before publishing, settle the licence and trademark questions in AGENTS.md under "Open, for the maintainer".

## Acceptance

Manual checks on real hardware, one per phase; record results in the Release checklist.

### Verifying the input engine (Phase 2)

Taps pass every event through unchanged in this phase (since Phase 4a the button tap swallows events for bound buttons, and since Phase 5a the scroll tap swallows mouse-wheel ticks while smoothing is on; see those sections below). To check the scroll filter:

1. Grant Accessibility (see above) and connect a mouse.
2. Open Settings → General. "Connected mice" lists the mouse; Input engine shows Buttons, Scroll and Modifier keys as **On**.
3. Scroll with the mouse wheel: the **Mouse wheel** counter rises.
4. Scroll with the trackpad or a Magic Mouse: only **Passed through** rises, and scrolling feels exactly as before.
5. Unplug the mouse: the list empties and the taps switch **Off**.
6. Turn off Settings → General → Scrolling (or the tray's Enable scrolling): Input engine → Scroll shows **Off**. Turn it back on.

### Verifying the button engine (Phase 4a acceptance, 5-button mouse)

1. Double-click the middle button (B3): Launchpad opens.
2. A single B3 click on a link opens it in a new tab, after a short wait for a possible double click.
3. B4 and B5 go Back and Forward in Safari (`Cmd+[`) and in Chrome.
4. B4 in Xcode and Notes does not change the text.
5. Left and right clicks are unaffected.
6. Trackpad clicks and scrolling are unaffected.
7. Turn off Settings → General → Mouse buttons (or the tray's Enable buttons): B3 does a plain middle click again.
8. Disable Mission Control's keyboard shortcut in System Settings, then click B3: Mission Control still opens (unreachable binding). This changes WindowServer hotkey state; restore your shortcut in System Settings afterwards if you changed it. Afterwards System Settings shows that shortcut as enabled with an unusual key: that is the unreachable binding MouseTune installed. Run it only with the maintainer's go-ahead.

### Verifying the Buttons editor (Phase 4b acceptance, 5-button mouse)

1. Settings → Buttons → + Add remap, press B4, choose Double click and Spotlight, then Add: a double click on B4 opens Spotlight, and a single click on B4 still goes Back after at most 260 ms.
2. Add a remap for B5 · Hold, choose Keyboard shortcut…, press ⌘⇧4, then Add: holding B5 shows the screenshot crosshair.
3. Try to add B3 · Click again: the "already set" message appears and Add stays disabled.
4. Restore defaults: the list and the button behaviour return to the Phase 4a defaults.
5. Start recording a shortcut and press ⌘Q: nothing quits, and ⌘Q is recorded.
6. Start mouse capture (+ Add remap), then close the Settings window: B3 still opens Mission Control.
7. Note whether macOS asked for Input Monitoring the first time you recorded a shortcut, and report it. It is assumed that Accessibility is enough; this step checks that.
8. Record ⌃→ for B4 · Click. Pressing B4 moves one Space right.

### Verifying smooth scrolling (Phase 5a acceptance, any wheel mouse)

1. Scroll a long page in Safari: it moves smoothly, eases out, and coasts briefly after the last tick.
2. Scroll to the top of a Safari page and keep going: it rubber-bands and springs back.
3. Spin the wheel fast, then slowly: fast spins travel much further per tick.
4. With the mouse connected, the built-in trackpad, a Magic Trackpad and a Magic Mouse (if you have one) scroll exactly as before.
5. Tray → Smooth scrolling off: plain notched scrolling again. Tray → Invert vertical scrolling on: the direction flips, with smoothing on and off.
6. If Accessibility Zoom is on, Ctrl + scroll still zooms the screen. Cmd + scroll in a browser behaves as it does without MouseTune.
7. Tray → Enable scrolling off in the middle of a coast: scrolling stops cleanly, and the next tick is plain.
8. Unplug the mouse in the middle of a coast: nothing keeps scrolling.
9. If a 60 Hz external display is connected, scroll on each screen: both are smooth.
10. With the pointer on an external display, unplug it in the middle of a coast: scrolling ends cleanly, and the next scroll is smooth.

Report how the scroll feels (too short a coast, too fast, too slow). The curve's constants are tuning knobs (`src-tauri/src/input/scroll/`).

### Verifying scroll modifiers and the Scroll screen (Phase 5b acceptance, any wheel mouse)

1. Shift + scroll in Safari scrolls sideways, smoothly.
2. Option + scroll moves a few pixels per tick.
3. With Accessibility Zoom on (System Settings → Accessibility → Zoom → "Use scroll gesture with modifier keys"), Ctrl + scroll still zooms the screen.
4. Settings → Scroll → *Scroll faster* = ⌃ Control: Ctrl + scroll is now faster and Zoom no longer gets it. Set it back to None.
5. Flick the wheel down three or four times in quick succession: each flick goes further than the last.
6. Turn on *Precise when scrolling slowly*: slow ticks move a pixel or two, a fast spin still flies.
7. Every Scroll-screen control changes the feel at once; the curve plot changes with smoothness, speed and precise.
8. Toggle *Smooth scrolling* in the tray: the Scroll screen follows, and the other way round.
9. Unplug or sleep the external display in the middle of a coast: scrolling stops cleanly without another tick.

### Verifying remaps beyond hotkeys (Phase 4c acceptance, 5-button mouse)

1. Settings → Buttons: change B4 · Click to *Middle click*. B4 on a link in Safari opens it in a new tab.
2. Add B5 · Click → *Double left click*. B5 on a word selects it.
3. Add B3 · Hold → *Play/Pause*. Holding B3 plays or pauses Music.
4. Try *Volume up* and *Brightness down*: the system HUD appears and the level changes.
5. Quit MouseTune, add `"com.apple.dt.Xcode": "CmdBracket"` to `nav_overrides` in `~/Library/Application Support/com.johnpaulalabe.mousetune/config.json`, start it again: B4 in Xcode now goes back in the editor's history. Remove the entry afterwards. Type the value exactly: anything other than `"CmdBracket"` or `"MouseButtons"` makes the whole settings file fall back to the defaults, with a recovery notice.
6. Set *Hold delay* to 500 ms, including releasing the drag off the slider: a hold needs a visibly longer press. Click *Restore timing defaults*.
7. Set *Double-click speed* to 400 ms: the double-click hint says 400 ms, and slow double clicks on a button with a double-click action register.

### Verifying buttons as modifiers and drag (Phase 6 acceptance, 5-button mouse)

Dock swipe and magnify are built but switched off until you verify them (see the next section). So today Spaces and Mission Control step, and zoom uses the keyboard shortcut.

1. Hold B3 and drag left or right: the Space follows your hand, one Space per drag, like a three-finger swipe. Drag left to bring in the Space on the right; drag right for the one on the left. Drag up: Mission Control opens. Drag down: App Exposé.
2. Releasing a drag never leaves Mission Control half open.
3. During a B3 drag the pointer stays still, and it moves again on release. Turn MouseTune off from the tray mid-drag, or unplug the mouse mid-drag: the pointer is free.
4. A B3 double click still opens Launchpad. A slow start with no movement does nothing until you release.
5. Set B5 · Drag to *Two-finger swipe*. In Safari a horizontal drag goes Back or Forward, and in Maps it pans.
6. Set B4 · Scroll to *Zoom*. Holding B4 and scrolling zooms Preview in and out with ⌘= and ⌘-. A button-bound Zoom works with no ⌘ held.
7. Set B4 · Scroll to *App Switcher*: hold B4, scroll to pick an app, release B4 to switch. ⌘ is released when you let go, so no ⌘ stays down.
8. Set a button · Acts as to *Middle button*. Holding it and moving drags like a real middle button (for example, panning with autoscroll in a browser).
9. Turn off *Freeze pointer while dragging*: the pointer now moves during drags.

Also check:

- Set the Zoom key to ⌘. With ⌘ physically held, scrolling still zooms on every tick in Safari and Preview.
- Revoke Accessibility in System Settings while a stand-in button (Acts as) is held: nothing stays stuck down afterwards.

### Turning on the interactive swipe and magnify (maintainer)

Both are off. Each has one `VERIFIED_ON` list; it stays empty until you have seen the probe work on your Mac. The probes post real events, so keep the terminal trusted for Accessibility and watch the screen.

1. `cd src-tauri && cargo test dock_swipe_events_read_back -- --ignored --nocapture` (posts nothing; must pass first).
2. `cargo test dock_swipe_moves_spaces -- --ignored --nocapture`. Use the default mode, with no `MOUSETUNE_PROBE_ENCODING`: it sends what MouseTune ships. Have two Spaces open. You should see Spaces slide and Mission Control open and close, each fully.
3. `cargo test magnify_probe -- --ignored --nocapture` with Preview or Maps frontmost: the image should zoom in, then out. Then run `MOUSETUNE_PROBE_MAGNIFY=ticks cargo test magnify_probe -- --ignored --nocapture`, which sends what one wheel tick sends.

Watch for Mission Control or a Space change that stays half done, or a zoom that jumps instead of following. If the screen gets stuck, press Esc or Ctrl-↑, or run `killall Dock`.

When a probe works, tell the agent what you saw. To turn it on, follow the flip checklists next to `VERIFIED_ON` in `src-tauri/src/platform/macos/dock_swipe.rs` and `src-tauri/src/platform/macos/magnify.rs`. After that, steps 1 and 6 above become the interactive swipe and the pinch zoom.

### Verifying launch at login and settings polish (Phase 7a acceptance, macOS 27)

Steps 1–3 need an app bundle signed with a stable identity. In `pnpm tauri dev` the app isn't a bundle, so Launch at login shows as unavailable.

1. Turn on Launch at login. It appears in System Settings → General → Login Items.
2. Log out and in. MouseTune is running, with no Settings window.
3. Turn it off in System Settings. Reopen General, and the switch is off.
4. Hide the menu bar item, then Quit from Settings. Launch MouseTune from Applications: Settings opens. Turn the item back on, and the icon returns.
5. Open logs folder shows the folder in Finder. The About link opens the browser.
6. Turn launch at login off in MouseTune, then on again; it still works (checks the `notFound` mapping).

### Verifying the release build (Phase 7b acceptance, macOS 27)

1. `APPLE_SIGNING_IDENTITY="Apple Development: <Name> (<TEAM>)" pnpm release`. Answer the prompts. The run ends with the report and every check passed.
2. Open the DMG, drag MouseTune to Applications, launch it, and grant Accessibility.
3. Run "Phase 7a acceptance" steps 1–6 on this installed app.
4. Rebuild with `pnpm release` and reinstall. Accessibility is still granted.
5. Paste the release report and the results. They get recorded in AGENTS.md and the checklist.

Not covered: public mode (no Developer ID credentials yet), Intel and macOS 12–26 (the checklist), and the DMG on another Mac.
